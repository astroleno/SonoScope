## 构建

使用 Node.js 22.13+、pnpm 8.15。首次安装执行 `pnpm install --frozen-lockfile`，然后 `pnpm check`。basePath 在构建时确定，默认 `/SonoScope`；改变后必须重建。需要根路径开发时设 `NEXT_PUBLIC_BASE_PATH=`。

发布前另运行 `pnpm audit:production`，使用官方npm审计端点；当前镜像不提供该接口。生产和开发依赖分别判断，不能通过忽略漏洞来令检查通过。旧TFJS源码仅保留开发兼容依赖，当前发布采用单一MediaPipe模型通路。

`pnpm build` 自动从锁定的 MediaPipe 依赖复制 WASM，并验证本地 YAMNet 模型 SHA-256。只使用同源资源。`pnpm package:release` 将 standalone、静态资源与 public 合并到 `release/`，排除所有 `.env*` 和运行配额文件。服务端运行 `release/app/server.js`。

必须在目标OS/CPU架构的环境安装和构建。当前本机副本为macOS arm64，包含macOS Sharp原生模块，不能直接认定可用于Linux服务器。发布包自带release-manifest.json和assert-platform.mjs；先在包根目录执行 `node assert-platform.mjs`，不匹配会退出失败。systemd模板也执行此检查。服务器Node路径须同时调整ExecStartPre和ExecStart。目标Linux构建与运行验证尚未取得。

`pnpm check` 包含发布副本检查，临时启动独立Node实例并验证入口跳转、API保护、模型/WASM/Worklet和所有静态文件，关闭真实云调用。可单独运行 `pnpm smoke:release`。若需核实当前密钥未进入客户端产物，在本地以 `node --env-file=app/.env.local scripts/smoke-release.mjs` 运行；脚本只报告是否发现泄漏，不输出密钥。报告存于 `test/artifacts/release-smoke.json`。

## 服务与密钥

单实例 Node 服务是当前支持的部署方式。多个 Node 实例不能各自使用独立配额文件，须先提供共享 QuotaStore 实现。

把 `app/.env.example` 的服务端字段放在 `/etc/sonoscope/server.env`，权限设为600，所有者为服务账号；不要放入站点 public、Git 或客户端环境变量。示例 systemd 文件在 `deploy/sonoscope.service`，使用专用 `/opt/sonoscope/node/bin/node`（22.13+），启动与平台检查使用同一路径。该目录目前只在本地模板中约定，未在服务器安装。腾讯云当前全局 Node 为20.19.5，不覆盖它；专用Node路径和运行账号须在部署前验证。

配额文件必须放在发布目录外，例如 `/var/lib/sonoscope/ai-quota.json`，账号对该目录有写权限。原子持久化和进程锁保护单实例；备份须保存完整文件。服务重启、版本回滚不得删除配额记录。未知上游用量按预留上限扣减。当前配额日按UTC划分，在北京时间08:00重置；这是当前实现口径，生产额度确认时需一并确认。

生产 AI 默认关闭。用户确认每日调用数、每日 token 上限及并发后，才设置 `AI_ENABLED=1`。未配置额度、无密钥或记录不可读时返回明确降级反馈，本地音频和弹幕继续。每客户端最短请求间隔10秒，滚动一分钟最多5次；一次调用的目标是5条普通弹幕与1–2条陪伴，512输出tokens默认、最大768，统一8秒截止，无隐藏重试或补单。

## 站点路由

先确认 `aitoshuu.me` 或 `aitoshuu.art` 的实际 HTTPS server 配置与现有应用。只在目标 server 内增加 `deploy/nginx-sonoscope.conf` 的 location，不覆盖站点根路由。`proxy_pass` 不加尾斜杠，保留 `/SonoScope` 前缀。

必须设置 `APP_ORIGIN=https://实际域名`；多个固定域名使用优先级更高的 `APP_ORIGINS=https://aitoshuu.me,https://tongye.me` 精确列表。只在受信代理覆盖 X-Real-IP 的情况下启用 `TRUST_PROXY=1`。节点端口仅监听127.0.0.1，公网不能直接访问。关闭 nginx/CDN 压缩和缓冲后，仍须验证整条链路实际逐条到达，响应头本身不是通过证据。

2026-10-15只读公网复查：`.me/SonoScope` 与 runtime-config/health 路径均返回同一份994字节的个人主页HTML（200），没有返回应用API；`.art/SonoScope` 及这些API返回404。报告见 `test/artifacts/public-host-check.json`。当前两个域名均未正确挂载本应用；内部upstream和可用资源仍需读取服务器配置。

DNS/APNIC核实 `.me` 使用阿里云地址 `47.103.120.24`，`.art` 使用腾讯云地址 `122.51.59.89`。2026-10-15用户扫码后，经两家官方网页终端完成只读核查，推荐现有腾讯云上海实例承载 `https://aitoshuu.art/SonoScope`：腾讯云2核4GB、可用内存2169MiB、剩余磁盘约30GiB、5Mbps/500GB月流量；阿里云2核2GiB、可用内存961MiB、剩余约12GiB、3Mbps。资源为当时快照，不能视为并发容量验收。详细脱敏证据见 `test/artifacts/server-comparison.json`。

两台都是Ubuntu 22.04、Linux x64和Nginx 1.24.0，配置检查通过，3100端口空闲。阿里云登录环境无Node，域名配置为 `/www/server/panel/vhost/nginx/html_aitoshuu.me.conf`，首页兜底导致 `/SonoScope` 返回个人主页。腾讯云域名配置为 `/www/server/panel/vhost/nginx/aitoshuu.art.conf`，引用现有PHP站点rewrite；没有SonoScope挂载。腾讯云已有一个80端口空server_name冲突警告，不影响当前语法检查；本轮没有修改其他站点配置。

建议落地方式：在腾讯云目标域名现有server块加入 `deploy/nginx-sonoscope.conf` 的两条location，保留PHP及其他路由；`APP_ORIGIN=https://aitoshuu.art`，单Node仅监听127.0.0.1:3100。Linux x64构建/验证后放入 `/srv/sonoscope/releases/<版本>/`，`current`指向已验证版本；专用Node放 `/opt/sonoscope/node/`，密钥与配额沿用上述外部目录。现有证书截至2026-11-24 05:58:57 UTC，正式发布前复查续期。当前仅准备本地方案与模板，未安装运行时、上传文件、修改代理或重载服务。

两台分别对DeepSeek和SiliconFlow的 `/models` 做3次不带凭据的连通性请求，均401，首字节约54–203ms。它只证明DNS/TLS/HTTP可达，没有调用模型，不能作为AI生成或NDJSON穿透代理的时延验收。

Next默认把 `/SonoScope/` 规范化为 `/SonoScope`。模板将两种路径都转发给Node，不能额外把无斜杠入口重定向回带斜杠入口，否则会形成循环。服务端 `redirect('/')` 已由框架添加basePath，不要再次手工拼接前缀。
