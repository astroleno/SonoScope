## 模块与关键接口

| 模块 | 职责与关键接口 |
| --- | --- |
| core | v2 FeatureFrame / FeatureSnapshot / GenerationRequest / StreamEvent / CommentCandidate；保留Hz、dB等单位和未知值。请求严格校验，禁止携带PCM。 |
| AudioSession | 音频资源唯一所有者；start / stop / dispose处理麦克风、文件、等待中取消、晚到资源与设备结束。文件流式播放，大小上限100MB。 |
| FeaturePipeline | DSP和模型各一个Worker；连续PCM、邮箱上限3、最近窗口及分类过期判断。onTiming提供计算耗时和特征就绪时间，不修改公开声音摘要契约。 |
| RuntimeMetrics | featureReady / rendered / snapshot(at?)按实际回调测量，直方图和窗口有界；传入当前时间时包含停止绘制后的零帧尾部。 |
| DanmuController / CommentQueue | 单队列≤12、显示间隔950ms、TTL和去重；audioSessionId与danmuRunId分开，停止取消请求。show(comment, { priority })允许首条AI和新本地观察替换最旧可见条目，普通AI批次不能抢占。 |
| DomCommentSink | 测量实际页头/页脚空白区，按换行后的高度排列，最多6条可见弹幕；放入区域成功才回执。历史只记录已回执内容，最多12条。 |
| Node接口 | /api/danmu/stream为同源v2 NDJSON；12KB请求体、6k字符Prompt、单次上游调用、绝对8秒截止。旧analyze/llm-danmu地址也仅接收v2，不兼容旧请求体。 |
| QuotaStore | 单进程锁、原子持久化、调用/token/并发限额、幂等、客户端速率限制；未知用量按预留上限扣记。多实例必须换共享存储。 |
| provider | SSE逐条解析，不等整批；根据可靠节拍/音乐分类约束Prompt及输出。空批次有反馈和冷却，partial如实保留，不隐藏重试或补单。 |

五个预设和黑白大字界面保留。共享页面提供明确开始/停止、文件输入、独立弹幕/频谱/AI开关、1–5/D/S、可见焦点、减少动态与静态记录。

### 提交前生命周期迭代

DSP准备期间本地分析立即产出；内部dsp-ready握手后才投递PCM。Worker脚本启动最多15秒，已投递任务仍以最老任务的2秒截止判断，最多3项邮箱；新任务回执不能延长旧任务。处理故障切回本地时重建分析器，避免使用启动阶段旧频谱产生假起音。静音仍推进频谱历史，但跳过最终必定未知的HPSS中值计算。

分类Worker新增model-loading握手，将脚本启动与模型初始化分开：两阶段各最多15秒，最坏准备30秒；重复握手不能续期，推理仍最多5秒，模型有效期仍3秒。公开声音/AI协议不变。前述15秒总初始化的旧冷启动记录对应旧发布副本，不能用于宣称本次版本已通过。

关闭AI会取消请求及计时器，移除未显示AI条目并释放它们的去重预留；已显示历史与本地条目保留。开关代次隔离旧回调，快速重开不会被旧取消结果置为失败。客户端8秒截止独立于传输层是否配合取消；缺少终止事件的返回明确失败，不会一直显示loading。请求节流、服务端配额、8秒上游截止和生产禁用规则未改变。

## 验收标准保持不变

2026-10-15用户回复“暂时不验收，或者你本机电脑验收也可以”：真实目标手机操作、麦克风与30分钟性能列为用户同意暂缓项，不阻塞本轮桌面和服务器调查。以下手机目标保留待复验；桌面45FPS目标未因此降低。

- 有效声音到本地首条显示p95≤1s，不把等待权限计入。
- 有效AI请求到首条实际显示p95≤3s，accepted事件不算首条；整批截止8s。
- 特征到绘制p95≤100ms；分别观察DSP计算、采集回调到特征就绪、特征就绪到绘制。它们的p95不能直接相加，也不是物理麦克风到屏幕的端到端延迟。
- 桌面与真实目标手机各30分钟；至少95%的一秒窗口分别≥45/30FPS；资源、监听器、队列和内存有界。
- 20次实际启停；等待权限、晚到Worker/请求、文件结束、设备断开和卸载不得串入新会话。
- 五档合成节拍60/90/120/150/180 BPM误差≤3，静音未知；真实音乐分类和弹幕依据另行验证。
- 320px、横屏、200%缩放、键盘、减少动态、读屏与权限/错误反馈；目标HTTPS和实际代理逐条传输NDJSON。
