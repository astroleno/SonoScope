用户在讨论“沿用现有 YAMNet 骨干、增加小型乐器专用头”后回复“你做一下吧”，批准在本地按此方向实施和验证。此方案沿用原 P0 质量、响应、数值、资源、生命周期与画面门槛；只有全部通过才替换应用默认模型。当前默认仍为 `yamnet-float32-1-temporal-2`，不得把候选或原默认模型的局部成绩写作新模型已通过。不增加 AI 调用、前端推理运行时或部署。

## 目标与数据边界

目标是在原 521 类通用声音能力不退化的前提下改善 Guitar、Piano、Percussion 的真实演奏覆盖，尤其保留两段历史吉他、弱/带噪演奏及近似乐器反例。训练特征必须取自当前 `app/public/model/yamnet-1.tflite` 的量化骨干：16 kHz 单声道、15,600 样本输入，内部 `layer28/reduce_mean` 为 `[1,1,1,1024]`、INT8，按该张量的量化参数还原用于浮点训练；不能把另一份 YAMNet 权重的特征误当成同一输入。原模型 SHA-256、来源、现有 521 类分数及全部旧失败保留。

训练数据首选 [OpenMIC-2018 原始音频与众包标签](https://zenodo.org/records/1432913)，校验压缩包和样本元数据。其页面标注数据集 CC BY 4.0，但逐曲目元数据还有原录音许可；本轮仅用逐曲目标明 CC BY / CC0 / Public Domain 的录音，排除 NC、ND、SA。标注按具体乐器部分填写：仅明确标注的正/负样本参与对应输出的损失，缺失标注不能当负例。按艺人/源曲目分组切分训练和调参集，严禁同一录音的相邻窗口分居两侧。工程中已有 62 段暴露演奏与控制只作开发回归，不能作为新盲集；两段 Ukulele、七段非音乐及全部历史失败都保留。训练和转换脚本、原始音频、逐窗分数存项目忽略的私有实验目录；公开报告只列可复核的哈希、划分、统计和结果，不复制录音。

## 模型与模块接口

1. **单个 TFLite 图。** 原量化 YAMNet 骨干和 521 类输出保持逐算子/逐权重一致；从其 1024 维特征分支做内置 `DEQUANTIZE`、小型全连接/ReLU/全连接/Sigmoid 乐器头。专用头使用 Guitar、Piano、Drums、Cymbals 四个独立 Sigmoid 输出，支持混合乐器。OpenMIC 的 Drums/Cymbals 各有独立的正负标注，不能在缺失另一项标注时训练一个合并的 Percussion 负例；应用将 Drums/Cymbals 的最大值映射为原 Percussion，不相加。Maraca/Tambourine 仍需在开发回归中单独确认，不能把鼓/镲训练视为覆盖了它们。输出 0 是原 AudioSet 521 类，输出 1 是专用头，分别带固定标签及 TFLite Metadata。只使用现有 MediaPipe 1.1.0 支持的内置算子、一个模型文件、一个分类 Worker 和一次分类调用，不增第二套浏览器推理运行时。
2. **私有训练/转换。** 固定原模型哈希、数据清单及随机种子；离线提取并缓存原骨干特征，保存分组划分、标签掩码、训练配置、权重、TFLite 及各阶段校验值。导出后逐窗比较 Python 参考、原 YAMNet 521 类和实际 MediaPipe 双输出；先证明数值与元数据可读，再测分类质量。训练集、调参集、62 段暴露回归、新独立集各自有不同用途，不把看过的失败反复重命名为盲测。
3. **core。** 为精确的新模型版本增加 YAMNet 输入 profile。按 `headIndex` 分别解析原 521 类和四个专用输出，类别名与输出长度严格校验；保留原通用类别、语音概率、未知/非音乐规则。专用头的概率只在其自身尺度竞争；不与原父/子类分数相加。独立的短时序策略先受原 Music/人声/近似乐器安全证据限制，再决定 Guitar、Piano、Percussion。通用 tracker 仍负责非目标乐器；通用 tracker 对三个目标的结果要经专用头确认，避免近似乐器从旧路径绕过。所有规则在开发集校准后冻结再接触新独立集。
4. **SDK / Worker / 应用。** `FeaturePipelineOptions.workerAssets` 仍是 `wasmUrl/modelUrl/modelVersion`，`ModelResult` v2、`ModelTiming`、单个在途请求、源代次/请求号、来源时钟、PCM 缓冲上限、超时降级、取消和关闭语义不变。Worker 对原版走原有单输出路径；候选版本显式验证两个输出和标签，将通用类别与候选乐器结果写回同一结果。应用只有在候选全部资格通过后才切换默认模型 URL/版本；原文件保持可回退。

## 不可放宽的验收次序

1. **数据/数值。** 训练/调参按曲目分组，公布类别/许可/样本数及哈希；重复提取一致。原输出在新图与原图逐类数值对照；专用头与训练参考及 MediaPipe 原生逐类对照。沿用浮点差 `≤2e-4`、前处理相关中间特征差 `≤0.005`、量化逐类差 `≤0.05`、每段覆盖下降 `≤3` 个百分点，并同时要求绝对质量通过。若头保持浮点，只记录实际量化范围，不把未量化分支称为量化通过。
2. **开发质量。** 对全部 62 段已暴露固定原片段逐窗跑原生模型：53 段正例每段正确覆盖 `≥80%`，未知/停顿计失败，首次正确来源时钟 `≤5s`；七段非音乐全观察零乐器，两段 Ukulele 不报错误具体乐器。必须逐例列出失败、首时钟及竞争标签，不能用平均分掩盖历史失败。只有开发质量通过才冻结模型、阈值、预处理、代码和哈希，另找至少六段真实独立演奏及相应非音乐控制，先冻结来源/片段/标注再揭示预测。
3. **真实链路与资源。** 新独立集仍逐段通过原覆盖/`≤5s` 可见针对性弹幕门槛；实际 Worker 计算 p95 `≤100ms`，模型文件 `≤8 MiB`，SDK 模型率 PCM 队列加在途输入 `<1 MiB`。20 次真实启停/切源/取消与冷启动须无跨源污染、超时或资源泄漏。最后用已批准的 Ego Lite 受控后台截帧条件跑五预设 `≥30min`，`≥95%` 完整秒 `≥45FPS`，切换/缺失秒照计，不降画质；普通后台限制仍单列。目标 Linux/HTTPS、物理麦克风和真实网络冷加载按上线验收分别记录，不以本机回环推断。

一旦任何必要质量门槛失败，保留模型、原始结果与失败证据并停止接入；不以修改标签或放宽门槛追认通过。没有全部资格前不切应用默认、不提交、推送或部署。数据或工具可得性问题先查清，不用静默减少交付范围。
