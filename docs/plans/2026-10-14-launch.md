## 模块与契约

- core：版本化 FeatureFrame / FeatureSnapshot / GenerationRequest / StreamEvent / CommentCandidate、校验和纯 DSP。
- SDK：AudioSession 独占音频资源；FeaturePipeline 合并窗口与 Worker 推理；Runtime 统一调度。Worker 工厂由应用注入。
- danmu-pipeline：一个控制器、一个有界队列、独立 audioSessionId / danmuRunId、取消与过期去重、显示回执。
- app：共享体验组件、原有 shader、Worker 入口、Node 服务、持久配额和兼容接口。
- 单实例 Node 部署；多实例须更换共享 QuotaStore，不能复制本地配额文件。

## 实施与验收顺序

1. 构建和回归基线：修正 workspace、包导出与声明，升级受支持框架，恢复类型和 lint 检查。
2. 安全和生命周期：密钥仅在服务端、严格请求上限、持久配额和幂等；重复 start、等待权限时 stop、旧结果不得进入新会话。
3. 音频链路：真实采样率、Hz 质心、连续频谱通量、未知 BPM 不填 120，Worker 中真实模型推理及可追踪降级。
4. 混合弹幕：本地首条目标 p95 ≤1s，AI 首条目标 p95 ≤3s，整体截止 8s；源标识、有界队列、文本/ID 去重、过期丢弃。
5. UI：明确开始/停止、弹幕和频谱独立开关、1–5/D/S 快捷键、可见焦点、缩放、减少动态、静态可读历史、权限和异常反馈。
6. /SonoScope：basePath 覆盖 API、Worker、模型和资源；生产构建、代理流式检查、部署和回滚说明。

目标值须用测量证明，不以模拟测试替代真实模型、真实服务、手机或服务器验收。30 分钟持续运行和 20 次启停覆盖资源增长；合成节拍 60/90/120/150/180 BPM 误差 ≤3。

## 提交前迭代（2026-10-15）

在既有AudioSession / FeaturePipeline / 单一弹幕队列架构内修复两处生命周期问题。公开v2契约不变：

- DSP Worker通过内部`dsp-ready`握手后才接收PCM；准备期间本地DSP立即工作。Worker启动最多15秒，已投递PCM的最老任务处理截止仍为2秒，邮箱仍最多3项。停止释放两个阶段的计时器，旧Worker不得切换新会话。
