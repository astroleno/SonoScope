# P0 纯端侧 DSP 方案（待目标确认）

用户提出将端侧能力收敛到 BPM、响度、频谱等基础分析。本文件是架构提案；尚未把现有分级反馈试验或原 P0 具名乐器验收改为纯 DSP。[同录音的路线比较](2026-10-24-p0-feedback-direction-comparison.md)表明纯 DSP 可以及时描述声音，但不能自行判断音乐；当前更值得先验证 DSP 优先、现有小模型只做高置信语义门控的方案。

## 体积与现状

- `test/artifacts/private/p0-20261021/yamnet-head/` 的 4.1G 是本地训练/评测工作目录，主要含 2.4G 的 OpenMIC 压缩包、755M Python 环境、626M GuitarSet 录音包；这些不会被应用加载。四输出候选 `.tflite` 是 4,391,477 字节（约 4.19 MiB），也尚未接入应用。
- 应用当前加载的 YAMNet 模型为 4,126,810 字节（约 3.94 MiB），通过单独的 MediaPipe Worker 运行。去掉模型路径可省去该模型、分类 Worker 及其 WASM 的运行时加载；具体下载/内存收益仍需浏览器实测。`app/public/model/` 还有不被当前入口引用的旧资产，是否从发布包清理须随正式方案单独核对。
- 已有 `FeatureExtractor` 在 DSP Worker 中计算 RMS、频段/谱质心、谱变化、HPSS 与启发式 tempo，画面已有声音特征回退。无需增加识别模型或音频分析依赖。

## 建议的行为与模块

1. **声音输入与分析**：继续使用现有 `AudioSession` / AudioWorklet → `FeaturePipeline` → DSP Worker。纯 DSP 试验入口不传 `modelWorkerFactory`、`workerAssets`；`FeatureFrame.model` 保持 `null`，`classification` 为 `unknown`，不伪造音乐、语音或乐器标签。采集时钟、来源代次和 Worker 失效回退仍按原契约。
2. **本地反馈**：在 `DanmuController` 增加显式 `dsp-only` 模式，使用有有效性检查的 RMS、频谱及当前帧变化描述；第一条必须有可测内容，静音不发。该模式禁止“音乐”“乐器”“人声”“节拍”等语义声称，也不调用云生成。固定开场语不计入验收。普通模式继续按原规则。
3. **BPM**：现有 `TempoTracker` 最少积累 6 秒起音包络并要求稳定，故不能把 BPM 作为“5 秒首条反馈”。既有 11 段非音乐对照中，3 段仍产生高置信 BPM；新 GuitarSet 200 BPM 演奏则估为约 100 BPM。因此当前数值只保留在诊断层，不展示为普通用户的音乐 BPM 或节拍弹幕。仅凭重复脉冲无法证明声音是音乐；后续若需要公开 BPM，必须另行通过带节拍标注的准确率、半/倍速和非音乐误报验收。
4. **界面与资产**：本地试验开关选择纯 DSP，状态文案写“基础声学分析”，不把有意禁用模型显示成故障；五种画面继续消费 `FeatureFrame.values`。先验证，不在试验阶段删除正常入口的模型资产；正式切换目标后再清理无引用模型/WASM并检查构建产物。

## 验收及已知边界

- 新录音按来源冻结哈希、标签、真实起声点和执行代码后，测量第一条**实际可见、由当前声音支持**的本地反馈是否 ≤5 秒；静音不应靠固定模板凑数。完整播放期间，非音乐/近似乐器对照不得出现乐器、音乐、人声或“稳定节拍”等无证据声称。逐条记录文本与依据。
- 录音要包括音量相近的演奏、雨/风、语音、周期性机器声及尤克里里等近似音。BPM 单列可用率、首次出现时间、误差、半速/倍速错误及非音乐误报；没有可靠估计时允许未知。保留生命周期、来源切换、资源上限和五预设 30 分钟帧率验收；不新增 AI 请求。
- 只识别声学特征，就不能保证区分演奏和环境声，也无法满足原来的“正确具名乐器覆盖 ≥80%”目标。若产品改为纯 DSP，这项 P0 目标需要明确替换为可信声学反馈目标，历史失败记录仍保留。

只读可行性核对：用现有 DSP 和分级反馈逻辑、强制 `model=null` 回放五段**已暴露**开发录音，雨声棒、雨声、演讲、尤克里里、钢琴都产生了声音特征描述；雨声、演讲、雨声棒无高置信 BPM，尤克里里与钢琴首次 BPM 分别约 8.4 秒与 7.9 秒。后续扩大的对照已证明该小样本不能支持“非音乐不报 BPM”的结论；详见[路线比较](2026-10-24-p0-feedback-direction-comparison.md)。这些是离线检查，不是纯 DSP 浏览器模式或性能验收。

参考：[Web Audio 频域/时域分析](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode)、[librosa 起音包络与节拍跟踪](https://librosa.org/doc/latest/auto_tutorials/01-intro/06-rhythm.html)。本方案优先复用现有实现，不要求安装这些库。
