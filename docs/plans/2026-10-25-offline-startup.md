# 断网冷启动补齐（2026-10-25）

## 本轮范围与决定

用户要求补齐离线冷启动，乐器识别尽力即可，其他实机与长期验收继续留档，不再长测。本轮沿用共享 Web 核心、现有录播格式与声学默认模式，不新增模型、推理运行时或付费调用。

已复核现有乐器证据：YAMNet 原独立集有吉他覆盖率 66.3% 与 26.5% 的失败；专用头第二批只有 5/6 正例通过，雨声棒覆盖率 41.18%，并有早期尤克里里误报。它们不是关闭模型开关就能修复的问题。本轮依用户给出的取舍保留声学描述及 SDK 原显式分类路径，不把乐器识别改记为通过，也不再启动模型筛选或长测。

离线目标：同一浏览器在该域名至少联网打开一次，提示“离线已就绪”后，关闭页面、断网再打开 `/SonoScope`，可以进入录播库，播放原音频、原弹幕与视觉状态；本地文件输入也不依赖网络。首次从未访问过、缓存被浏览器清除及跨域录播共享不在此保证内。

## 模块与接口

- 构建：Next 生产构建后生成 `app/public/sonoscope-sw.js`，从该次构建枚举全部静态 JS/CSS/Worker 等资源；将同构建的公开主页面与 Mochi HTML 固定在 Worker 中，避免更新期间混用新旧 HTML 和脚本。版本包含构建 ID 与内容哈希。
- Worker：只处理当前源内、明确列出的应用页面与静态资源；API、POST、模型/WASM、用户音频及其他站点路径不进入应用缓存。安装完整后才可激活；失败保留旧版本。更新等待旧页面关闭，不强制接管、刷新或中断录制。只清理自己路径前缀的旧应用缓存，不触及录播的 IndexedDB/OPFS。
- 注册与状态：主体验内注册生产 Worker；`SONOSCOPE_PREPARE_OFFLINE` 消息检查并补齐本版本缓存，通过消息端口返回就绪结果。沿用页脚样式显示准备中、就绪、离线或更新待重开；失败不阻塞声音及录播。
- 部署接口：Worker 响应禁止 HTTP 缓存，设置 `Service-Worker-Allowed` 为无尾斜杠的应用前缀，注册范围同为 `/SonoScope`，覆盖现有无尾斜杠入口。两个公网域名分别注册和保存。
- 录播与云端接口：不改存储版本、音频所有权、回放时钟或生成协议；离线时运行配置请求失败仍按现有逻辑关闭 AI。

## 短验标准

1. 针对性测试验证资源清单、无尾斜杠入口、缓存不完整/安装失败、旧版本清理边界、API 与跨源请求绕过、离线 HTML 安全隔离头及不强制更新。
2. 生产构建、lint、类型与发布短验通过；新增 Worker 确实随独立发布包交付。
3. 实际浏览器联网完成准备，保存一段短录；关闭该测试页面，新页面在禁用网络和 HTTP 缓存下打开入口，查看、播放/暂停录播及原弹幕；核对画面和离线提示。只做秒级检查。
4. 更新失败不破坏旧缓存、缓存丢失不虚报就绪；旧录播不删除。手机/Windows/Safari 完整流程、实体麦克风、跨设备格式和 30 分钟指标仍未验，不改记通过。

实现与本地短验完成后，用户于 2026-10-25 明确批准本轮 commit、push、腾讯服务器部署及两个域名同步更新。沿用 main、现有 Node 服务和反向代理，仅追加必要的发布与离线冷启动短验；乐器识别先保留，不运行长测。实际发布结果另补入验证记录。

参考当前安装的 Next 16.4.2 PWA 指南、[MDN 注册范围](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register)及 [Service Worker 生命周期](https://web.dev/articles/service-worker-lifecycle)。
