# 2026-10-25 公网部署记录

## 已批准目标与接口

用户明确要求 commit、push 并部署公网，不再运行长测，剩余验收缺口如实保留。沿用当前 main 分支；与本功能无关的自适应主题计划不进入提交。

- 应用本体：腾讯云上海现有 Linux x64 服务器，单 Node 实例，监听 `127.0.0.1:3100`，独立服务账号与 Node 22 运行时。
- 公网主入口：`https://aitoshuu.me/SonoScope`。
- 同步入口：`https://tongye.me/SonoScope`，地址栏保持 tongye.me，不做域名跳转。
- 两个域名当前均解析到阿里云 `47.103.120.24`，保持域名及现有根站点；只为 `/SonoScope` 添加 HTTPS 反向代理。腾讯 `aitoshuu.art` 作为验证证书的 HTTPS 上游，最终转发至回环地址的应用。
- 服务端新增 `APP_ORIGINS` 精确来源列表，配置为 `https://aitoshuu.me,https://tongye.me`，优先于原单值 `APP_ORIGIN`；不启用通配 CORS，仍拒绝 cross-site 请求。原单域部署兼容。
- 生产 AI 保持关闭；不迁移凭据、不发起付费模型调用。录播保存在访问者当前域名的浏览器存储中，两域名不共享录播列表，可用备份导出恢复。

## 发布短验

复用已通过的 225 条工程测试与录播短测证据，关键录播源码哈希仍相同。针对新增来源列表补测合法双域、第三方／协议变化／伪装后缀拒绝及原单域兼容。在 Linux x64 上构建与打包，确认平台检查、健康接口、静态文件、Worker、生产诊断页隔离、AI 关闭、同源保护及两个 HTTPS 页面可运行。公网浏览器只做必要的音频文件、弹幕和录播回看短验。

发布目录保留版本号与来源提交；切换前保存现有站点配置，先通过 nginx 语法检查再 reload。失败时恢复本轮配置及 current 指向，不改动其他站点。
